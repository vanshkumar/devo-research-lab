## Required separation and enforcement limits

1. Give the PI an explicit allowed-action list: reconcile status/usage, read bounded returns and exposure summaries, rank alternatives, write bounded briefs/decisions, reserve work and request a distinct review. Delegate scientific source reconstruction, scientific searches, data transforms, simulation, fitting, calibration, diagnostic code and numerical sweeps. “Input-only”, “quick check” and “planning” must not exempt numerical work.
2. Require a preflight record before dispatch or scientific execution: active/paused state, human authority and local date, applicable usage floor, unique owner/reservation, explicit runtime model/effort, approved brief hash, owned paths, deadline, remaining task/review/revision budgets and exact access class. Deny missing/ambiguous fields and reconcile uncertain prior dispatches before retrying. A pause must prevent both queued wakeups and resumptions from launching new work.
3. Tie review to frozen artifact hashes and a separate reviewer identity. Distinguish PI inspection, implementation replay, independent reconstruction and scientific calibration. The author of a decisive scientific artifact cannot supply its independent signoff. Preserve old failed gates and exposure records across every amendment and successor.
4. Use a narrowly routed command/tool path and, where the host supports it, actual role-based tool/file/network restrictions. A Python preflight, JSON flag, hook or Markdown contract alone is a cooperative gate when the same PI can directly invoke an unrestricted shell, browser or dispatch tool or edit the gate. Record that limitation plainly; do not claim a hard token ceiling, complete process isolation or guaranteed protected-data nonaccess without platform enforcement and independent traces.

Proposed learning for PI integration: this lab's cycle-7 registry explicitly permitted a PI input-only scientific diagnostic, which the PI authored and ran despite investigator execution ownership. Keep scientific computation in an assigned investigator work unit; classify execution by its function rather than by input-only/unfitted labels. Confidence: high.
